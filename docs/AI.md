# MaxTransit：以 CargoDist 為核心的客運 AI

| 項目 | 內容 |
|---|---|
| 日期 | 2026-10-16 |
| 目標 | 設計一個 OpenTTD AI：用 CargoDist 的策略讓公車、鐵路、飛機各自發揮最大價值，並以**乘客安全第一**、**節省時間**為主要目標 |
| 位置 | `ai/MaxTransit/`（Squirrel，OpenTTD Script API 15，約 5,000 行） |
| 結果 | 在 OpenTTD 15.3 以無頭模式跑完 6 種情境（原版車輛、OpenTTD-Max NewGRF、CargoDist 開關、三種墜機設定）共 73 個遊戲年，另加存檔讀檔測試：**所有情境 0 事故、0 腳本錯誤、0 迷路列車** |

## 1. 優先順序

AI 的每個決定都依同一個順序判斷：

1. **安全**：不安全的方案直接否決（hard veto），不拿來和收益比較。
2. **時間**：乘客的門到門時間（走到車站、候車、乘車）換算成價值，算進每個方案的評分。
3. **價值**：在前兩項之內，讓每一筆投資、每一輛車的淨收益最大。

「安全」不只指不撞車：列車在單線上永遠只有一列、號誌區間數就是列車數上限、不蓋任何平交道、不在會淹水的地方施工。這些規則寫在建設與路徑搜尋裡，不是事後檢查。

## 2. 遊戲機制依據（OpenTTD 15.3 原始碼查證）

### 2.1 飛機墜毀

`aircraft_cmd.cpp` 的 `MaybeCrashAirplane()`。飛機降落滑行時（`AirportMovingDataFlag::Brake`），只要速度高於滑行速度 × `plane_speed`，每次移動（每 tick 兩次）都會擲一次骰子：

- 大型機（`AIR_FAST`）在短跑道機場（Small、Commuter）：每次 3276 / 2^22，**與「飛機失事」設定無關**，只有作弊選項「no jet crashes」能關掉。
- 其他情況：設定為「無」時不擲；「減少」時 (0x4000 << 1) / 1500 = 21，「正常」時 43（擲出 ≤ 該值即墜毀）。

煞車公式是 `UpdateAircraftSpeed()` 的 `cur_speed − max(1, cur_speed² / 16384 / plane_speed)`。從進場速度 230 × plane_speed 減到 50 × plane_speed，大約要擲 154 次（飛機速度 1/1）到 286 次（1/4）。換算成**每次降落**的墜機機率：

| 飛機速度設定 | 「減少」 | 「正常」 | 大型機降落 Small / Commuter |
|---|---|---|---|
| 1/1 | 0.08% | 0.16% | 11%（約 9 次 1 次） |
| 1/2 | 0.12% | 0.23% | 16% |
| 1/4（預設） | 0.15% | 0.30% | 20%（約 5 次 1 次） |

實測：在「減少」設定下讓 AI 飛約 2,700 次降落，發生 3 次墜機（約 0.11%），和模型相符。AI 的 `SafetyOfficer.LandingProbability()` 就是用這個模型逐機型計算。

> **既有文件的更正（已修正）**：`docs/M5-REPORT.md` 原本說大型機在小機場「有 3276/2^22 ≈ 0.08% 的墜機率，設定『飛機失事』為『無』時不會」，`data/README.md` 也寫「遊戲設定『飛機失事』非『無』時」才有風險。兩處都不正確：0.08% 是**每次擲骰**的機率，一次降落會擲上百次，實際約 11–20%；而且這個風險**不受設定影響**。兩份文件都已依此更正。

### 2.2 其他事故

| 事故 | 來源 | AI 的對策 |
|---|---|---|
| 平交道撞車（`CRASH_RV_LEVEL_CROSSING`） | 道路車輛停在平交道上 | 鐵路遇到道路一律用橋或隧道；公車路線不經過任何平交道；城鎮在我方軌道上蓋的平交道，每月稽核時拆除，並替城鎮蓋一座跨軌公路橋（城鎮會在道路盡頭繼續延伸，不給橋就會一再蓋回來） |
| 列車相撞（`CRASH_TRAIN`） | 同一區間兩列車 | 未裝號誌的單線只放一列車；複線用單向路徑號誌（PBS one-way），列車數 ≤ 號誌區間數；更新車輛時單線先撤舊車再發新車 |
| 淹水（`CRASH_FLOODED`） | 海平面、海岸地格被海水淹沒 | 所有建設避開高度 0 與海岸地格，機場外圍再留一格 |
| 飛機找不到機場（`CRASH_AIRCRAFT_NO_AIRPORT`） | 目的地機場被拆 | 有飛機飛往的機場不拆；稽核確認每座機場都有機庫 |
| 所有事故 | — | 事故地點列入 `danger_tiles`，以後不再在那裡施工 |

### 2.3 時間與票價

- 每格行駛時間：所有車種都是 2048 / 速度（km/h）tick（`AIEngine.GetMaxSpeed` 已經除過 `plane_speed`）。一天 74 tick。
- 斜線軌道每格是直線的 2/3；同一節車廂長度內轉兩次彎會被限速 88 km/h（`GetCurveSpeedLimit`），所以路徑搜尋對連續轉彎加重懲罰。
- 乘客票價隨運送時間下降：每個貨物老化週期（預設 185 tick ≈ 2.5 天）少 1/255，超過 24 個週期（約 60 天）後每週期少 2/255（`GetTransportedGoodsIncome`）。也就是說，快的車本身就賺得多。

### 2.4 CargoDist

- 需求由 link graph 分配：對稱模式下 A→B 的量受兩端中較小的一方限制，距離越近的目的地越有吸引力。
- Script API 可讀到規劃結果：`AIStation.GetCargoPlannedVia(A, B)`（MCF 求解後，從 A 經下一站 B 的月流量）、`GetCargoWaitingVia`、`AIStationList_CargoPlannedByVia/FromByVia`。
- 同一個站（join 在一起的 station）裡換乘不用走路；不同車站之間必須有交通工具連接，乘客才會轉乘。

## 3. 策略

### 3.1 安全（`lib/safety.nut`）

**硬性否決**（違反就不蓋、不派車）：

- 飛機機種 × 機場：大型機永遠不派往 Small、Commuter；直升機場只給直升機。
- 航程：訂單距離超過機型航程就不開航線。
- **空中政策**（AI 設定 `air_policy`）：「飛機失事」設定不是「無」時，每次降落都有上表的隨機風險。預設 **2 = 不載客飛行**；1 = 只在比鐵路省 40% 以上時間時飛；0 = 哪裡最好就飛。設定為「無」時，配對正確的航線風險為 0，AI 會正常使用飛機。
- 時間優先：同一對城鎮，只要鐵路的門到門時間不比飛機慢，就不規劃航線（除非那條鐵路蓋不成）。
- 鐵路：不碰道路（不產生平交道）、不在淹水風險格、不做 90° 急彎、分岔與匯流只設在前後各兩格直線的位置（否則會形成 90° 轉向，列車無法通過而迷路）。
- 列車數上限 = 號誌區間數；單線 = 1。

**每月稽核**：重查已建好的一切，包括航線機種、機庫、平交道（城鎮可能新蓋）、列車數、公車路線上的平交道。發現問題就撤車、改路或關閉路線，並記錄在年度安全報告。

**事故反應**：事故地點列入禁建區；平交道事故的路線關閉；列車相撞的路線降回一列車，直到號誌重新檢查。

**保養**：鐵路與公車的班表兩端都有「需要時進廠保養」的車庫指令。其餘車輛的可靠度低於該車型最高值的 3/4 時送修，同一輛車 120 天內最多送一次。

### 3.2 時間（`lib/timemodel.nut`、`lib/fleet.nut`）

- **時間模型**：單程 = 行駛格數 × 每格時間 + 停站（起停 + 依座位數的上下客時間）。門到門 = 單程 + 班距 / 2（平均候車）。
- **時間價值**：每位乘客每天的時間以票價的 0.25 / 0.5 / 1%（「班次」設定：經濟 / 平衡 / 頻繁）計價，從方案價值中扣除。所以較快、班次較密的方案會勝出，即使票價收入相同。
- **實測校正**：每條線派一輛「量測車」記錄真實來回時間，回饋到模型（例：鐵路實測約為估計的 1.1–1.4 倍）。不到估計值一半的「來回」不採用（那不是完整的一趟）。
- **時間稽核**：抽樣每輛車在行駛、停站、等號誌、故障、進廠的時間比例，以及平均速度占最高速度的比例，寫進年度報告。
- **班距**：每種運具有目標最大班距（平衡：公車 6、鐵路 12、飛機 15 天）。現金超過一百萬時，只要每車還能坐滿四分之一，就加車把班距壓到目標內，也更早把單線升級為複線。

### 3.3 價值與 CargoDist（`lib/planner.nut`、`lib/cargodist.nut`、`lib/network.nut`）

**一個城鎮一個樞紐**：公車站、鐵路站、機場盡量 join 成同一個 station（`station_spread` 允許的範圍內），轉乘在站內完成。機場太遠無法 join 時，用接駁公車連接兩站。另外在樞紐附近加兩個「步行站」（join 進樞紐的公車站，不派車），擴大樞紐的乘客涵蓋範圍。

**共用車站**：新鐵路線若一端的城鎮已有複線車站，就從既有路線的出發軌道分岔、匯入到達軌道，共用同一座車站，兩條線的乘客就能在那裡換車。年度 CDIST 報告會列出每個樞紐的轉乘量，例如情境 F1 的「Frintston：每月規劃 684 人次，其中 488 人在此轉乘，往 Larnpool South 322、往 Great Slaningville 267」。

**運量以 CargoDist 為準**：每 15 天比較各線的規劃流量（planned via）和運能（車數 × 座位 × 30 / 來回天數）。規劃量超過運能或月台積人時加車，長期使用率很低時減車。CargoDist 關閉時，改看候車人數與車站評價。

**候選方案評分**：每對城鎮依距離評估各運具：公車 ≤ 45 格、鐵路 28–260 格、飛機 ≥ 60 格（受空中政策限制）。用時間模型選出最佳車型，再算價值 = 年票收 − 營運成本 − 折舊 − 乘客時間成本。

- 新鐵路一開始是**單線、一列車**，所以用一列車評估，並為成長預留 60% 運量，選出的會是大運量列車。
- 資金不足時以「每英鎊價值」排序；資金充足時，真正稀缺的是施工時間（AI 的運算預算），因此每個方案的成本至少以可用資金的六分之一計，等於改用絕對價值排序。
- CargoDist 網路效應：能把新城鎮接進網路的方案價值 ×1.35；樞紐有大量 A↔B 轉乘時，直達線加上轉乘紅利。
- 資金充足時，新鐵路開通當天就鋪好第二條軌道與號誌；每完成一個大工程，順便蓋一條最佳公車線（幾天就能完工）。

**試過但預設關閉**：城內接駁公車（設定 `feeders`），把市區較遠街區的乘客載進鐵路樞紐。實測載客量增加，但在 CargoDist 下，每個公車站都是新的獨立車站，會把原本的長途需求分流成市內短程旅次，鐵路收入因此下降：

| 2003 年車輛利潤（同一版程式的 A/B 測試） | 關閉 | 開啟 |
|---|---|---|
| 512×512，種子 20261016 | £1.3M（11 鐵路） | £589k（8 鐵路、10 公車） |
| 512×512，種子 777 | £934k | £844k |

## 4. 鐵路建設細節（`lib/rail.nut`、`lib/pathfinder.nut`）

### 4.1 車站

兩月台的端點站：月台 L 格（`max_train_length`，最多 6）、三格咽喉含兩組渡線、最遠端是車庫。row 0 出發、row 1 到達，咽喉裝單向 PBS 號誌。

**選址**：在城鎮半徑內找能放下整個佔地矩形（兩列 × L+5 格）、高低差 ≤ 1 的地方（必要時整地），月台涵蓋的乘客要有市中心的 30%，或位在步行範圍內。砍樹會降低城鎮評價（每棵 −35），所以限制可砍的樹數，並在附近補種（每棵 +7）。市區太密時，半徑放大 8 格、涵蓋要求減半再找一次。

**出口檢查**：每列的出口都要用真正的鐵路規則（轉彎、坡度、橋）跑一次短搜尋，確認能離開車站 10 格以上，否則不選這個站址。

**佔位軌**：車站一蓋好，四個出口格（每列兩格）就先鋪上與路線垂直、不接任何軌道的短軌，城鎮不會在鐵軌上蓋房子。路徑搜尋把這些格子當成空地，真正鋪軌時才拆除。沒有這一步時，一次幾十天的路徑搜尋期間，城鎮常常把出口蓋掉。

### 4.2 路徑搜尋

完整搜尋是 A*，狀態包含格子、進入方向、前一步方向與「剛轉過彎」旗標，成本就是行駛時間：直線 30、斜線 20、每轉 45° 加 45、連續轉彎再加 90、坡道 20、橋 120、隧道 150。安全規則（不碰道路、不碰淹水格、不做 90° 彎、坡上只能直線）寫在可通行判斷裡。

在預設「中等」AI 速度下，腳本每 4 tick 才執行一次，每遊戲天約 18.5 萬個 opcode，A* 每展開一個節點約 650–900 opcode，也就是每天只能搜幾百個節點。直接搜尋時，一次失敗要花 100–330 遊戲天。因此改成兩段：

1. **粗略走廊搜尋**（`CorridorFinder`）：每格只有一個狀態，可以直線跳過水面、道路、軌道（橋），但會用遊戲的試建模式確認橋真的蓋得起來；坡地只能沿坡向直線通過；橋頭不能接另一座橋。兩端先各做一次「能否走出 16 格」的檢查，口袋地形幾百個節點內就會失敗。
2. **完整搜尋**限制在粗略路線左右 3 格的走廊內，並以「沿粗略路線剩下的距離」當啟發值，引導它繞過湖泊，而不是鑽進正對終點的死巷。若在走廊內卡住，就記下卡住的位置，讓下一條粗略路線避開那附近 2 格，最多三輪。

效果：之前失敗的 Sedingworth–Futown（跨湖、繞城）從約 14,000 個節點仍失敗、耗時 110 天，變成 826 個節點、28 天就找到；一般路線多半在 5–30 天內完成。

### 4.3 複線、號誌、分岔

第二條軌道沿第一條鋪設（相鄰格有成本折扣），兩條都每隔數格裝單向 PBS 號誌，咽喉另有號誌。施工時先讓列車回車庫，裝完號誌再發車。共用車站的新線在既有複線的直線段上用道岔分岔與匯流，且前後各兩格都必須是直線。

### 4.4 NewGRF 列車編組

- **固定編組**（articulated multiple unit，自帶座位）：整列購買，不再加掛車廂。長度未知時，以每 84 座一節 8/8 車廂估計。
- **自由編組**：先頭車（dual-headed）只掛**同系列**的中間車（名稱前綴相同即視為同系列；中文、日文名稱以非 ASCII 字元作為斷詞點）。中間車本身有動力，不受機車功率限制。其他系列的中間車不會被拿去配別的車頭。
- **實測**：蓋好車庫後、選定車型之前，會在車庫實際買一輛車頭與一節車廂，量出長度、確認能否連掛，再立即賣回（新車賣回是全額）。若超過月台長度或無法連掛，就換下一個候選。
- 在 OpenTTD-Max 套件下，AI 實際選用過「Transrapid SMT 先頭車 + 10 節中間車」（1,068 座、428 km/h）、固定編組 Transrapid SMT（445 座）與 Transrapid 09（150 座、498 km/h，用在短線）；原版車輛下是 AsiaStar、T.I.M.、X2001 加客車。

## 6. 設定

| 設定 | 選項 | 預設 |
|---|---|---|
| `use_road` / `use_rail` / `use_air` | 是否建公車、鐵路、機場 | 全開 |
| `air_policy` | 0 哪裡最好就飛 / 1 只在省 40% 時間時飛 / 2 隨機墜機開啟時不載客飛行 | 2 |
| `feeders` | 城內接駁公車 | 關 |
| `frequency` | 經濟 / 平衡 / 頻繁（時間價值與目標班距） | 平衡 |
| `expansion` | 慢 / 普通 / 快（施工間隔 120 / 40 / 12 天，資金多時縮短） | 普通 |
| `debug`、`debug_signs` | 開發用：詳細日誌、車輛軌跡、地圖傾印；施工位置標誌 | 關 |

建議的遊戲設定：「飛機失事（Plane crashes）」設為「無」，AI 才會用飛機；「允許城鎮建造平交道（Allow towns to build level crossings）」關閉，AI 雖然會自己處理，關掉更乾淨；乘客的 CargoDist 設為對稱。

## 7. 測試結果

工具：`tools/ai/run_ai.py`（OpenTTD 15.3 無頭模式，null 影像與音效驅動，預設 AI 速度與 opcode 預算）。`make ai-test` 跑 5 年，`--load` 從存檔接續，`--ai-tar` 改用打包好的 tar。

| 情境 | 地圖 / 起始年 / 年數 | 設定 | 最後年報的路線（公車 / 鐵路 / 飛機） | 車輛 | 年度車輛利潤 | 累計載客 | 事故 |
|---|---|---|---|---|---|---|---|
| F1 | 256² / 1990 / 20 | 原版車輛、CargoDist 對稱、飛機失事「正常」（其餘皆為預設） | 9 / 13 / 0 | 94 | £927k（2008） | 169,419 | 0 |
| F2 | 512² / 1995 / 10 | 同 F1 | 5 / 12 / 0 | 66 | £1.7M（2003） | 92,524 | 0 |
| F3 | 512² / 2016 / 8 | OpenTTD-Max NewGRF、飛機失事「無」、列車長 8 格、貸款上限 £5M | 1 / 3 / 11 | 74 | £1.8M（2022） | 51,308 | 0 |
| F4 | 256² / 1960 / 15 | CargoDist 關閉（manual） | 2 / 14 / 0 | 22 | £367k（1973） | 81,204 | 0 |
| F5 | 512² / 1995 / 10 | 飛機失事「減少」、`air_policy` = 0 | 5 / 10 / 0 | 47 | £1.4M（2003） | 56,455 | 0 |
| F6 | 512² / 1995 / 10 | 飛機失事「無」 | 4 / 6 / 7 | 121 | £3.3M（2003） | 131,714 | 0 |

觀察：

- **安全**：六個情境的安全報告都是 0 事故、0 罹難。安全否決在 F3 擋下 104 個「機種與機場不符」的方案，F6 擋下 42 個；「列車數超過號誌區間」的方案也一律否決。城鎮在我方軌道上蓋的平交道，每月稽核時拆除，F1、F2、F4 都有幾處因此改成公路橋。
- **運具分工**：允許安全飛行時（F3、F6），長距離（400–700 格）由飛機負責，中距離由鐵路負責，近距離與一般城鎮間由公車負責；F6 三種運具並用，利潤也最高。「減少」設定加上 `air_policy` = 0（F5）時，AI 依然沒有開航線：1995 年的原版飛機在 1/4 飛機速度下，門到門時間不比鐵路快，所以被「時間優先」規則排除。
- **CargoDist 樞紐**：F1 的 Frintston 每月 684 人次中有 488 人在此轉乘，Duhattan Springs 312 人次中有 144 人轉乘。
- **時間**：鐵路實測來回時間約為模型估計的 1.1–1.4 倍（含加減速與停站），量測值會回饋校正模型。
- **資金**：中後期現金持續累積（F2 約 £5.6M），瓶頸在施工速度，見第 9 節。

存檔與讀檔：預設 512² 地圖跑 4 年後存檔，讀檔再跑 3 年，AI 回報「restored 7 lines from the savegame」並繼續擴建到 9 條鐵路、2 條公車線（線路、樞紐、量測資料都寫進存檔；存檔不能放浮點數，所以以 ×100 的整數保存）。打包後的 `MaxTransit-1.tar` 也用 `--ai-tar` 實際載入測試過。

## 8. 開發中發現並修正的問題

| 問題 | 原因 | 修正 |
|---|---|---|
| 墜機風險低估約 200 倍 | 把每次擲骰的機率當成每次降落的機率 | 依煞車步數計算每次降落機率；預設空中政策改為不載客飛行 |
| 單線上出現兩列車 | 汰換時先發新車再撤舊車 | `BuildFor` 硬性檢查列車數上限；單線汰換先撤舊車 |
| 共用車站的列車大量迷路（26 列） | 單線路線未鋪的出口格沒有預留，別的路線接進來；拆除時刪光了共用車站的月台 | 所有車站出口格列入預留；拆車站逐格處理 |
| 新支線的列車迷路 | 分岔點選在斜線的下一格，形成 90° 轉向，列車不能通過 | 分岔／匯流前後各兩格必須是直線 |
| NewGRF 下完全不蓋鐵路 | 固定編組又加掛車廂、拿 N700 中間車配 AsiaStar、長度用猜的 | 固定編組不加掛、系列鎖定、車庫實測 |
| 路徑搜尋一次失敗花掉半年 | 終點出口被包圍、橋頭只准平地、opcode 預算小 | 出口檢查、斜坡橋頭（試建判斷）、粗略走廊 + 引導搜尋 + 卡點重繞；每節點 opcode 降 1.5 倍 |
| 粗略路線可行、完整搜尋不可行 | 粗略路線用了坡度不合的橋、兩座橋共用橋頭、無視坡向 | 粗略搜尋也做試建、橋頭後必須直行、坡地沿坡向 |
| 橋可能拆掉民房 | OpenTTD 建橋時會清除橋下的房屋 | 橋下只允許空地、水面、道路、軌道 |
| 搜尋期間城鎮蓋住出口 | 搜尋耗時數十天 | 佔位軌 |
| 城鎮反覆在軌道上蓋平交道（一條線 45 次） | 拆掉後道路盡頭還在，城鎮又往前蓋 | 拆除後替城鎮蓋跨軌公路橋 |
| 老車型在起點和車庫間來回，永遠到不了終點 | 每月可靠度低於 45% 就送修，但車型最高可靠度只有 50% 左右 | 鐵路、公車靠班表內的保養指令；其他車輛門檻相對化並加冷卻期 |
| 現金大量閒置 | 以每英鎊價值排序、單線只能一列車 | 資金充足時改用絕對價值、開通即複線、加班次、公車副線 |
| 大城鎮找不到站址 | 市區沒有完整的空地 | 擴大搜尋範圍；仍不行時，把既有路線升級為複線以便共用車站 |
| 空中政策 2 時日誌洗版 | 每對城鎮都印一行「不規劃航線」 | 政策 2 時完全不評估航線，只在開局說明一次 |

## 9. 限制

- 不用船；郵件只隨飛機的貨艙運送。
- 施工速度受 AI 運算預算限制（「中等」AI 速度下，每遊戲天約 18.5 萬 opcode）。地形破碎的地圖上，一條鐵路從搜尋到完工常要 1–3 個月，中後期現金因此累積。把「AI 速度」調快或提高 `script_max_opcode_till_suspend` 能直接加快擴張。
- 成長中的大城鎮常找不到站址，此時只能共用既有車站。若第二條軌道也鋪不出去，該線維持單線一列車。
- 鐵路網只用同一種軌道時才能共用軌道（電氣化、單軌、磁浮彼此不通）；不同軌道的路線仍可 join 在同一車站轉乘。
- 地圖上若有其他公司的道路車輛，城鎮新蓋的平交道在下一次稽核（最多一個月）前仍有風險；關閉「允許城鎮建造平交道」可完全消除。

## 10. 安裝

- 從原始碼：把 `ai/MaxTransit/` 複製到 OpenTTD 使用者資料夾的 `ai/` 底下。
- 打包：`make ai-bundle` 產生 `build/bundle/MaxTransit-1.tar`（含 readme、changelog、GPL v2 授權），放進 `ai/` 資料夾即可，與 BaNaNaS 的格式相同。
- 在遊戲的「AI / Game Script 設定」中選 MaxTransit，再調整上面的設定。
